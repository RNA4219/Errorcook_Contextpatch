# Downsized Cookbook Summary

このドキュメントは、ワークフローの要点と日本語での返答方針を要約します。

- 実装はテスト駆動開発を基本とし、先にテストを作成します。
- リポジトリの既存ルールを自動検出して厳密遵守します。
- 公開APIの破壊を避け、不可避時のみTASKSに追記します。
- 実装時は型安全・例外設計・後方互換性を優先します。
- import順序は標準→外部→内部、空行で区切ります。
- 副作用は utils/provider_spi 層に限定します。
- 作業スコープは合計130行/3ファイルまで。超える場合は分割提案。
- 非機能要件として、実行コストは±5%以内を目標。

> 注意: このリポジトリの実装方針を満たすよう、今後の変更はこの方針に沿って進めます。
